# 示例笔记

这是一篇放在 `notes/` 子目录下的笔记，用来演示本文档站如何按目录对内容分类。相比 `guide/` 里偏教程性质的文档，`notes/` 更适合存放日常记录、调试心得、临时方案这类零散内容。

## 今天在做什么

今天主要在调一个 React 组件的渲染问题。页面在数据为空时没有给出友好的提示，而是直接渲染出一个空白区域，体验很差。记录一下最后的处理方式，方便以后回顾。

问题的核心在于：组件直接用列表数据去 `map`，没有区分「加载中」「空数据」「有数据」这三种状态。

## 修复后的组件

把三种状态显式拆开之后，逻辑清晰了很多：

```jsx
function ArticleList({ loading, articles }) {
  if (loading) {
    return <p className="tip">加载中，请稍候…</p>;
  }

  if (articles.length === 0) {
    return <p className="tip">暂无内容，去写第一篇吧！</p>;
  }

  return (
    <ul className="article-list">
      {articles.map((item) => (
        <li key={item.id}>{item.title}</li>
      ))}
    </ul>
  );
}
```

## 三种状态对照

把状态和对应的界面表现列成一张表，一目了然：

| 状态     | 触发条件               | 界面表现         |
| -------- | ---------------------- | ---------------- |
| 加载中   | 请求尚未返回           | 显示「加载中」   |
| 空数据   | 返回成功但列表长度为 0 | 显示空状态提示   |
| 有数据   | 列表存在内容           | 正常渲染列表     |

## 复盘要点

回头看这个问题，可以总结出几条：

- 状态要显式区分，不要用一套渲染逻辑硬扛所有情况
  - 加载中要有反馈
  - 空数据要有引导
- 列表渲染务必带上稳定的 `key`
- 空状态文案尽量给用户一个「下一步动作」的提示

## 关于目录分类

这篇笔记之所以放在 `notes/` 而不是 `guide/`，是因为它属于个人经验记录，不是面向所有读者的标准教程。通过这种目录划分，文档站的左侧导航能把「教程」和「笔记」清晰地分开，读者也更容易找到想看的内容。
