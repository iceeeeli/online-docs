## 二、项目 A · 消费者小程序（C 端 MP，2025 全年主线）

C 端车主小程序，核心围绕延保 + 理赔两大业务链路：

- **延保（Warranty）**：临时页搭建 → phase1 → phase2 完整迭代；统一车辆信息选择组件、车牌 OCR 识别、爱车数量限制（≤3 辆）、车牌轮胎数限制校验与接口对接、重复提交按绑定状态分弹窗。
- **理赔（Claim）**：OCR 车牌识别、总里程数独立采集、表单精简（去车架号/爱车信息/地址）、字段对齐后端。
- **合规与上报**：隐私授权兜底、Legal/Sales Team 文案与授权弹窗逻辑、首页扫码/延保服务渠道路径与事件埋点上报、新老用户状态传递。
- **稳定性**：小程序安全兜底导致的过期页闪现、点击穿透、缓存一致性、表单校验重构提公共工具函数等细节打磨。

## 三、项目 A · B2B 经销商全端（经销商 MP / H5 / CMS，2026 主战场）

主线「零售商管理」+ 四端协同，工作量最大、最体现系统性：

- **零售商管理**：列表/详情、营业执照多图、所属经销商下拉过滤停用项、信息查重（按地址去重）、发起合同、权限码显隐替代岗位硬编码。
- **合同（Contract）**：列表/详情/发起/历史合同全链路、Step2 防重复提交（按钮锁+loading+互斥）、签署人/经办人字段口径、电子签错误提示、多字段缺失改弹窗渲染。
- **理赔（Claim）管理**：列表/详情/审批/操作按钮矩阵、时间线对齐 PCR、权限码与数据范围、备注弹窗、业务反馈按钮数据守卫、OCR 识别向导。
- **质保（Warranty）数据管理**：CMS 质保清单+详情、轮胎位置 frontRear + tireSpecs 多选、子表列宽按内容权重分配、状态多选筛选、脱敏、导出。
- **二维码（QRCode）管理**：列表/详情/搜索筛选/导入导出、批量作废/导出独立权限码、导出上限 2 万行、来源枚举、D1 收货方/发货方列。

> 全程坚持四端一致性（MP/H5/CMS/B2C 口径对齐）、文档体系化（API spec 同步、tech-plan、bug 台账、待确认项闭环），建立规范化项目管理流程。
